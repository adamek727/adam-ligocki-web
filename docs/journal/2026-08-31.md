# 2026-08-31

Work driven from the `adam-freelance` repository, which is the source of truth
for every fact on this site. Decisions taken there on the same day are journalled
in `adam-freelance/docs/journal/2026-08-31.md`; this file records only what
happened to the site.

## 19:00 — the site collapsed from six routes to one page plus a blog

Adam's brief, in his words: *"a single page with several sections, something like
presentation of myself, my skills, my clients, contact on me, and maybe link to a
blog"*, *"some lightweight design, not something complicated"*, and the line that
actually settled the design: *"this web can be linked in a meeting."*

A link pasted into a meeting is read once, by someone with no context, in about
twenty seconds. That rules out navigation. Everything a visitor needs is now a
section of `/{lang}/`.

**Rebuilt in place rather than starting a new project.** The repository already
carried the blog, RSS, dark mode, the GitHub Pages deploy and a green CI gate. A
fresh static page would have had to re-earn all of it. The rebuild is net
deletion: nine route and component files removed, one page rewritten.

Removed: `about.astro`, `services.astro`, `contact.astro`, `thank-you.astro`,
`projects.astro`, `projects/[...slug].astro`, `ProjectLayout.astro`,
`ProjectCard.astro`, `ServiceCard.astro`, and the placeholder content
(`example-project.md`, `hello-world.md`, the four `pages/*` bodies per language).

Kept: the blog, its tag pages, RSS, the 404, the theme toggle and the language
switcher.

The contact form went with `contact.astro`. `web3formsKey` was still
`REPLACE_ME`, so the form had never rendered, and a `mailto:` link needs no third
party at all. `web3formsKey` was deleted from `src/config.ts` as orphaned. So was
`cvPdfAvailable`, whose only reader was the deleted About page.

## 19:00 — where the copy lives now, and why not in the component

`src/content/pages/<lang>/home.md` carries the hero and the `skills` groups in
frontmatter and the biography in the body. `src/content/projects/<lang>/*.md`
carries one file per client. `src/i18n/ui.ts` was cut back to chrome only:
navigation, section headings, button labels and the three proof numbers.

The rule the repository already stated — content in markdown, never in component
code — is what makes the next change cheap. Adam can rewrite his own biography
without opening an `.astro` file.

`src/pages/[lang]/index.astro` reads `home.md` through `import.meta.glob` with an
explicit `HomeFrontmatter` interface, so a typo in the frontmatter is a type
error rather than a blank section.

## 19:01 — the skills grid was wrong on the first render

Four skill cards in `.grid--cards` (`auto-fill, minmax(18rem, 1fr)`) laid out

## 19:02 — verification, and a headless-screenshot trap worth remembering

`npm run check` (astro check, production build, internal link checker):
`0 errors, 0 warnings, 0 hints`, 5 pages built, `OK: 6 pages, no broken internal
links`. Down from 22 pages, which is the point.

Rendering was checked in both languages and both themes with headless Chromium
against `astro preview`.

Two things cost time and are worth writing down:

1. **The snap-confined Chromium cannot write into `/tmp/claude-*`.** It fails
   with `Failed to write file ... No such file or directory (2)`, which reads
   like a missing directory and is actually confinement. Writing the screenshot
   under the user's home directory works.
2. **`chromium --headless --screenshot` ignores a URL fragment.** It always
   captures from the top of the document, so `#clients` shows the hero. Worked
   around by writing a temporary copy of the built HTML with the earlier sections
   removed, serving it from `dist/`, and deleting it afterwards. Light theme was
   forced the same way, by stamping `data-theme="light"` on a copy, because the
   theme is chosen by a script reading `localStorage` that headless has no way to
   set.

## 19:20 — the design direction stopped being invented and started being inherited

Two instructions, minutes apart. First: *"try to make it better. Use design
superskills and make it modern. Also, by default light-gray theme with soft blue
elements."* Then, while I was mid-plan: *"i like the CV_ligocki_slate theme. lets
use this pdf."*

The second one changed the work more than the first. I had been designing a
visual identity from scratch around the idea of instrumentation. Adam already
had one — the "slate" theme in `adam-freelance/scripts/build_cv.py` — and he had
just told me he liked it. Inventing a second identity for the same person would
have been the wrong answer even if it had been a better one.

So the site is now derived from the CV, value for value:

| | Slate CV | Site token |
|---|---|---|
| Headings | `#17324a` | `--fg-heading` |
| Mono channel labels | `#6f8ba3` | `--fg-label` |
| Panels | `#f2f6f9` | `--bg-subtle` |
| Hairlines | `#dbe3ea` | `--border` |
| Rules and left borders | `#7c93a8` | `--border-strong` |
| Display / body / data | Archivo / IBM Plex Sans / IBM Plex Mono | same three |

The canvas is `#eaeff4`, a light grey-blue that did not exist on the CV, because
the CV is printed on white paper and a screen is not paper. Cards are white on
that grey, which is where the depth comes from — there is almost no shadow in
the design.

The CV's structural device came across too: every section is announced by a
tracked uppercase monospace label over a hairline rule, exactly as `h2` works on
the CV. That is what makes the page look like an engineer's document rather than
a template.

## 19:20 — light stays light, even on a dark machine

`prefers-color-scheme: dark` no longer switches the theme. Adam asked for
"by default light-gray", and the page's whole purpose is being pasted into a
meeting: it should look the same to everyone in the room, not different
depending on each person's operating system. Dark is still there, opt-in through
the toggle, and a stored choice still survives a reload without a flash.

This is a deliberate break with the usual advice to respect the system setting.
Reversing it is one block in `tokens.css` plus the `matchMedia` fallback in
`ThemeToggle.astro`.

## 19:25 — the fleet plot: the one chart, and the one risk

The ULLMANNA entry now declares a `fleet` block in its frontmatter and renders
200 cells, the first 10 filled, captioned `10 machines, 2023` → `200 machines,
2026`. The strongest fact on the site is drawn at true scale instead of claimed
in a sentence.

The risk: a data visualisation in a personal site can read as decoration. It is
justified here because the growth *is* the claim, the numbers are already
cleared for public use, and a reader sees the ratio before reading a word. Cells
fade in over 400ms, staggered 2ms apart, and the whole animation is inside a
`prefers-reduced-motion: no-preference` guard.

It is deliberately the only chart. The schema comment says so, and the README
says so, because the second one would make both of them decoration.

## 19:27 — two layout bugs found by screenshot, not by reading the CSS

1. **Dead space above the name.** Making the masthead rule span both columns put
   the portrait and the identity block in the same grid row with
   `align-items: end`. The portrait was 17rem tall and the identity about 9rem,
   so the name was pushed down by the difference. Fixed by sizing the portrait
   to 12.5 × 14rem so the two columns end together just above the rule.
2. **The mobile header did not wrap.** `.site-nav { order: 3; width: 100% }` did
   nothing, because `.site-header__inner` is a flex row with the default
   `flex-wrap: nowrap` — a 100% width on a non-wrapping flex item just shrinks.
   Adding `flex-wrap: wrap` inside the same media query gave the intended two
   lines: name and controls, then the nav.

Both were invisible in the source and obvious in a picture.

## 22:10 — the slate-derived design was rejected, and the reason was the interesting part

Adam: *"honestly, i do not like the web design. it is too much machine-like.
just a lot of text. Can you make some more modern design? somethinkg fresh."*

Both halves of that are correct and they have the same root cause. I had taken
"he likes the slate CV theme" and carried it onto the web literally: monospace
uppercase channel labels over hairline rules on every section, desaturated
blue-grey, dense paragraphs. That is a good CV. A CV is a dense document read by
someone who has already decided to read it. A website is scanned for twenty
seconds by someone who has not.

**The mistake was treating a liked artefact as a liked style.** He said he liked
his CV. He never said he wanted his website to be his CV.

Two decisions taken with him rather than guessed again, after missing once:

- **Layout: a bento grid**, over a big editorial page and over a drifting
  point-cloud hero. Chosen because it fixes the real complaint structurally —
  tiles cannot hold paragraphs, so the copy has to be short. Being fashionable is
  a side effect, not the argument.
- **Copy: cut hard.** About went from four paragraphs to two short ones. Skills
  went from six to eight items per group down to four. The strapline, the
  highlight block and the proof strip all disappeared into tiles.

## 22:15 — what the bento is made of

Fourteen tiles on a four-column grid: identity (2×2), portrait (1×2), three stat
tiles, about (2×1), languages, five clients, skills and contact (both full
width so their inner columns lay out in one row instead of two).

Two things carry the design and nothing else does:

1. **One inverted tile.** ULLMANNA is deep navy with white text; every other
   tile is white or softly tinted. That single inversion is where the page gets
   its colour and its hierarchy. A second one would make it noise, so the CSS
   comment and the schema comment both say exactly one entry should set
   `featured`.
2. **The fleet plot**, kept from the previous version but now on navy: 200 cells
   with the first 10 bright. Contrast of the dim cells was raised from 22% to
   32% of the foreground because at 22% they disappeared into the tile.

Dropped: IBM Plex Mono, everywhere. It was the single biggest contributor to the
"machine-like" feeling. Type is now Archivo for display and IBM Plex Sans for
everything else, and the site loads one font family fewer.

Layout control lives in the content: `wide: true` in a client's frontmatter
makes its tile span two columns, `featured: true` inverts it. Adding a client is
still a markdown file, not a CSS change.

# 2026-09-01

## 18:22 — a reference site replaced two rounds of guessing

Adam: *"try something more like https://www.vladan.cz/, but just for software
development, robotics and ai/ml."*

Screenshotted the reference with headless Chromium rather than describing it
from the HTML, because the thing being asked for is visual. What it actually
does, in order of how much it matters:

1. **Full-bleed alternating blocks.** No container, no cards. A tinted image on
   one side, a panel of words on the other, flipping side each block.
2. **One tint over every photograph.** His is deep green. Pictures taken on
   different days with different cameras all read as one site because of it.
   This is the whole identity.
3. **Large uppercase serif headings**, centred, letterspaced, low contrast.
4. **Three or four short centred sentences per block.** No paragraphs anywhere.
5. **A big-number band** across the full width.

The third round in a row on this design, and the first with a reference. Worth
recording that the reference solved in one screenshot what two rounds of my own
proposals did not.

## 18:25 — the honest problem: this style is built on photography and he has none

vladan.cz works because of his own pictures of boards, benches and instruments.
Adam has no project imagery and his portrait arrives later.

Rather than pretend, each block renders a generated pattern in the tint —
`points` like a LiDAR return, `grid` like a calibration target, `bars` like a
spectrum — and swapping in a real photo is one line: put the file in `public/`
and add `image: file.jpg` to that block in `home.md`. `.block__visual img`
applies the tint and the crop, so any photograph drops into the family.

Told him plainly that the layout will look markedly better once real pictures
exist. Building it as if the photos were there, and leaving the slots obvious,
seemed better than choosing a design that hides the gap.

## 18:26 — what changed, structurally

The page is now `hero → numbers → robotics → AI/ML → software → who you work
with → selected work → contact`. The three service blocks are exactly the three
areas Adam named. That also makes the site service-led rather than CV-led, which
is a commercial improvement independent of the visual style.

Type changed with it: Source Serif 4 for display, IBM Plex Sans for body. Both
were already in the CV builder's font list, so the family stays his. Archivo and
IBM Plex Mono are gone.

Colour follows `strategy` rather than the previous brief: one blue family from
`--ink` through `--deep`, `--mid` and `--pale`. His earlier "light-grey with soft
blue" is still there in the pale panels, but the page is no longer
light-dominant, because the reference is not.

## 18:29 — the header bug, and why the clever version lost

I first made the header `position: absolute` and transparent, so it floated over
the dark hero exactly as the reference does. It looked right on the home page and
made the header **invisible on the blog**, where the background is pale and the
header text is light.

I had also set `body { background: var(--ink) }` to stop a pale strip appearing
under the last block. That turned the blog page dark while every text token
stayed light-theme, so the blog's `<h1>` rendered navy on navy and simply was not
there. Two changes, each defensible alone, combining into a page with an
invisible title.

Both reverted. The header is now a solid sticky dark bar on every page. It is
slightly less elegant over the hero and it is readable everywhere, which is the
better trade — and it gives back navigation while scrolling, which the absolute
version had silently removed.

The pale strip turned out not to exist on the real page at all. It was an
artefact of the truncated test file I was screenshotting, where `main` was
shorter than the viewport. **I fixed a bug that my own test harness had
invented**, and the fix broke a real page.
